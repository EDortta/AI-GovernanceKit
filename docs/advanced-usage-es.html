Referencia del CLI

Detalles avanzados de uso

Todos los comandos y parámetros de GovernanceKit, incluida la instalación de AI-Agents, identidad por instancia, diagnóstico, reanudación y presupuestos de contexto.

Sintaxis global

governancekit [--root PATH] [--version] COMANDO [OPCIONES]
--root PATHSelecciona el repositorio. Es global, debe aparecer antes del comando y usa el directorio actual por defecto.
--versionMuestra las versiones de GovernanceKit, AI-Agents predeterminada y AI-Agents del proyecto, incluido el estado de actualización.
-h, --helpMuestra la ayuda global o del comando seleccionado.

install-agents

# Instalación nueva
governancekit --root /proyecto install-agents

# Actualización de una instalación existente
governancekit --root /proyecto install-agents --upgrade
--ref REFTag, branch o commit de AI-Agents. Por defecto: v1.1.6 con checksum.
--repo OWNER/REPORepositorio alternativo. Por defecto: EDortta/AI-Agents.
--forceSobrescribe archivos existentes del kit.
--upgradeActualiza archivos del kit preservando el estado propio del proyecto.
--docs-onlyActualiza documentación gestionada sin tocar AGENTS.md ni adaptadores.
--install-awtInstala el helper descargado agent-worktree.sh en PATH.
--trackMantiene la documentación del kit rastreada por Git y guarda la elección.
--no-trackMantiene esa documentación fuera de Git; incompatible con --track.

configure e identidad

El archivo canónico es .governancekit-identity.json. Es local, ignorado por Git y usa modo 0600. WORKSPACE.md no es obligatorio ni satisface el gate de identidad.

governancekit --root /proyecto configure \
  --operator-name "Nombre" --host-id "host-01" \
  --instance-path "/proyecto" --sibling-path "/otro-checkout" \
  --assigned-ports "3000,8000" --branch-ownership "feature/mi-branch"
ParámetroObligatorioDescripción
--set KEY=VALUENoCompleta un placeholder heredado; repetible.
--operator-name NAMESíNombre del operador humano.
--host-id IDSíIdentificador estable de máquina o instancia.
--instance-path PATHSíRuta absoluta de este checkout.
--sibling-path PATHNoOtro checkout que puede disputar branches o recursos.
--assigned-ports PORTSNoPuertos reservados separados por coma.
--branch-ownership BRANCHNoBranches operadas por esta instancia.

Validación y orientación

doctorValida archivos, readiness, identidad, secretos, estado y posibles colisiones de branch.
doctor --jsonProduce resultados estructurados para CI.
map --output PATHEscribe el mapa en otra ruta; por defecto docs/codemap.md.
map --allIncluye símbolos Python privados con guion bajo.
resumeMuestra trabajo activo, próximo paso, handoff, identidad, branch y alertas.

discover y configuración compartible

governancekit --root /proyecto discover --json
governancekit --root /proyecto configure-project plan \
  --project-name "Repo de ejemplo" \
  --domain payments --capability reconciliation \
  --agent codex --provider openai:env:OPENAI_API_KEY:primary \
  --json
governancekit --root /proyecto configure-project apply \
  --project-name "Repo de ejemplo" \
  --domain payments --capability reconciliation \
  --agent codex --provider openai:env:OPENAI_API_KEY:primary \
  --json
governancekit --root /proyecto configure-project show --json

discover informa si el repositorio parece nuevo o existente y detecta lenguajes, frameworks, gestores de paquetes, comandos, archivos de gobernanza e integraciones locales. configure-project guarda el estado compartible del proyecto en .gk/project-config.json.

--provider usa el formato NAME[:MODE[:CREDENTIAL_REF[:ROLE]]], donde MODE puede ser manual, env o file-ref; ROLE es primary, fallback u optional.

classify-change y sesiones de aprobación

governancekit --root /proyecto classify-change plan \
  --summary "Separar el flujo de onboarding" \
  --label behavioral-change --label security-sensitive \
  --rationale "Introduce un gate adicional para datos sensibles" \
  --domain identity --capability onboarding \
  --compatibility "Requiere actualización coordinada del cliente" \
  --residual-risk "Puede fallar la automatización heredada" \
  --json
governancekit --root /proyecto classify-change apply \
  --summary "Separar el flujo de onboarding" \
  --label behavioral-change --label security-sensitive \
  --rationale "Introduce un gate adicional para datos sensibles" \
  --domain identity --capability onboarding \
  --compatibility "Requiere actualización coordinada del cliente" \
  --residual-risk "Puede fallar la automatización heredada" \
  --json
governancekit --root /proyecto config-session start --interactive
governancekit --root /proyecto config-session approve --approval project-config-review --json
governancekit --root /proyecto config-session show --json
governancekit --root /proyecto config-session apply

classify-change escribe la clasificación en .gk/change-classification.json. Las etiquetas admitidas incluyen additive, behavioral-change, contract-change, migration y security-sensitive.

config-session start --interactive carga las fuentes del índice docs/required-reading.md, usa el idioma operativo y guía cada respuesta estructurada con explicación, ejemplo y separación visual. Guarda el agente, el dominio primario de cada capacidad y, para cada proveedor, finalidad, rol, modo y solo la referencia de credencial; la clave nunca se guarda en la configuración del proyecto. Los archivos locales de credenciales están protegidos y excluidos de git. primary es el valor predeterminado, fallback se usa si falla y optional no participa por defecto. Los valores guardados o pendientes reaparecen como valores predeterminados en el próximo upgrade. Una sesión pending_approval significa que el plan está guardado en .gk/config-session.json, pero aún no se aplicó: ejecute config-session approve --approval <token> para cada aprobación listada, revise con config-session show y después ejecute config-session apply. El terminal imprime los comandos exactos y explica qué revisa cada aprobación.

bootstrap-issue

governancekit --root /proyecto bootstrap-issue \
  --epic-number 010 \
  --epic-title "Adoptar nuevo límite de autenticación" \
  --task-title "Crear tarea de migración" \
  --owner "Ana" \
  --related-commit planned
--epic-numberPrefijo numérico obligatorio para la carpeta local del épico.
--epic-titleTítulo obligatorio del épico usado para derivar el slug.
--task-titleTítulo obligatorio de la primera tarea.
--ownerResponsable renderizado en las plantillas.
--related-commitReferencia planned o final del commit escrita en los archivos.

Hooks y voz opcional

governancekit --root /proyecto install-hooks --hook-type pre-commit --force --json
governancekit --root /proyecto voice-integration detect --json
--hook-typeActualmente admite pre-commit.
--forceReemplaza un hook local ya existente.
--jsonEmite en JSON el resultado de instalación del hook o de detección de voz.

voice-integration detect busca un binario opcional de AI-ListenToMeOnCLI (o AI_LISTENTOMEONCLI_BIN) sin convertirlo en dependencia obligatoria.

Contexto determinista

governancekit context inspect --task implementation --risk runtime --issue PATH --json
governancekit context build --task review --risk security --telemetry
governancekit context telemetry prune --manifest PATH
--task TYPESelecciona contratos de tarea; por defecto implementation.
--risk RISKAñade una categoría de riesgo; repetible.
--issue PATHIncluye la issue activa.
--manifest PATHUsa otro manifiesto de contexto.
--jsonEmite decisiones y conteos en JSON.
--telemetryEn build, registra solo metadatos, sin contenido.
telemetry pruneElimina telemetría anterior a la retención configurada.

Secuencias comunes

# Primera configuración
governancekit --root /proyecto install-agents
governancekit --root /proyecto configure
governancekit --root /proyecto doctor

# Actualización segura
governancekit --root /proyecto --version
governancekit --root /proyecto install-agents --upgrade
governancekit --root /proyecto doctor

Script auxiliar para CI: scripts/validate-governance.sh /proyecto ejecuta juntos doctor --json y discover --json.
