CLI reference

Advanced usage details

Every GovernanceKit command and parameter, including AI-Agents installation, per-instance identity, diagnostics, session resume, and deterministic context budgets.

Global syntax

governancekit [--root PATH] [--version] COMMAND [OPTIONS]
ParameterDescription
--root PATHSelects the repository to operate on. It is global, must precede the command, and defaults to the current directory.
--versionShows GovernanceKit, default AI-Agents, and project AI-Agents versions, including upgrade status.
-h, --helpShows global help or help for the selected command.

install-agents

# Fresh install
governancekit --root /project install-agents

# Update an existing installation
governancekit --root /project install-agents --upgrade
--ref REFAI-Agents tag, branch, or commit. Default: checksum-pinned v1.1.6.
--repo OWNER/REPOAlternative source repository. Default: EDortta/AI-Agents.
--forceOverwrites existing kit files.
--upgradeUpdates kit-owned files while preserving project-owned state.
--migrate-contentWith --upgrade, extracts legacy project-specific agent contracts from .docs-migration-bak/ into docs/project-rules/. Required before upgrading an orphaned migration.
--docs-onlyRefreshes managed documentation without touching AGENTS.md or tool adapters.
--install-awtInstalls the downloaded agent-worktree.sh helper onto PATH.
--skip-project-configurationSkips the default offer to start the required-reading-driven project scope interview.
--trackKeeps kit documentation tracked in Git and saves the choice to .governancekit.
--no-trackKeeps kit documentation out of Git; mutually exclusive with --track.

Adoption modes: --review is the interactive default; --quick applies high-confidence generated documents; --advanced retains the granular session flow. Automation must use --non-interactive --accept-generated; generated policy is never accepted implicitly.

configure and identity

The canonical file is .governancekit-identity.json. It is local, gitignored, and mode 0600. WORKSPACE.md is not required and does not satisfy the runtime identity gate.

governancekit --root /project configure \
  --operator-name "Name" --host-id "host-01" \
  --instance-path "/project" --sibling-path "/other-checkout" \
  --assigned-ports "3000,8000" --branch-ownership "feature/my-branch"
ParameterRequiredDescription
--set KEY=VALUENoFills a legacy placeholder; repeatable.
--operator-name NAMEYesHuman operator name.
--host-id IDYesStable machine or instance identifier.
--instance-path PATHYesAbsolute path of this checkout.
--sibling-path PATHNoAnother checkout that may contend for branches or resources.
--assigned-ports PORTSNoComma-separated ports reserved by this instance.
--branch-ownership BRANCHNoBranches operated by this instance.

Without identity flags, an interactive terminal prompts for missing fields. When flags are used, provide all required fields.

config-session

governancekit --root /project config-session start \
  --project-name "Demo" \
  --domain backend \
  --capability api \
  --agent openai-agents \
  --provider openai:env:OPENAI_API_KEY:primary \
  --json

governancekit --root /project config-session approve --approval project-config-review
governancekit --root /project config-session show --json
governancekit --root /project config-session apply

Use config-session start --interactive to load the sources selected by docs/required-reading.md. The selected, locally authenticated agent runs in read-only mode and proposes domains with source evidence before the operator reviews them. The interview follows the operational locale, explains each choice, and retains saved or pending answers as defaults. Providers are collected as name, purpose, routing role, mode, and credential reference: primary is the default route, fallback is used when it fails, and optional is not selected by default. API keys are never stored in project configuration; local credential files are protected and gitignored. The operator-started interactive interview in install-agents and install-agents --upgrade accepts symlinks under .credentials/ without broadening source access. Direct config-session use can explicitly do the same with config-session start --interactive --credentials-allow-symlinks. A JSON credential profile may contain api_key (or apiKey/key) plus optional model and base_url; values are used only in memory. A pending_approval session means the plan is saved in .gk/config-session.json but is not applied: run config-session approve --approval <token> once for every listed approval, inspect with config-session show, then run config-session apply. The terminal prints the exact commands and explains what each approval reviews.

Deterministic context

governancekit context inspect --task implementation --risk runtime --issue PATH --json
governancekit context build --task review --risk security --telemetry
governancekit context telemetry prune --manifest PATH
--task TYPESelects task contracts; default is implementation.
--risk RISKAdds a risk category; repeatable.
--issue PATHIncludes the active issue in context selection.
--manifest PATHUses an alternative context manifest.
--jsonOutputs context decisions and counts as JSON.
--telemetryOn build, appends metadata-only telemetry without content capture.
telemetry pruneDeletes telemetry older than the manifest retention policy.

remove-agents

governancekit --root /project remove-agents plan --with-llm --json
governancekit --root /project remove-agents apply --plan .gk/remove-agents-plan.json --accept-project-extractions

Only an unchanged file matching the installation manifest is removed. With --with-llm, a configured primary provider may propose splitting project-specific text from a modified kit file. Review the exact plan first: applying an extraction requires --accept-project-extractions, writes it beneath docs/project-rules/, indexes it in required reading, and backs up every affected file under .gk/remove-agents-backup/.

Common sequences

# First setup
governancekit --root /project install-agents
governancekit --root /project configure
governancekit --root /project doctor

# Safe update
governancekit --root /project --version
governancekit --root /project install-agents --upgrade
governancekit --root /project doctor
