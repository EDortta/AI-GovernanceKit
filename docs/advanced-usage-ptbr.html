Referência do CLI

Detalhes avançados de uso

Todos os comandos e parâmetros do GovernanceKit, incluindo instalação do AI-Agents, identidade por instância, diagnóstico, retomada e orçamento de contexto.

Sintaxe global

governancekit [--root PATH] [--version] COMANDO [OPÇÕES]
ParâmetroDescrição
--root PATHDefine o repositório operado. O padrão é o diretório atual. É um parâmetro global e deve vir antes do comando.
--versionMostra a versão do GovernanceKit, a versão padrão do AI-Agents e a versão registrada no projeto, indicando upgrade disponível.
-h, --helpMostra a ajuda global ou a ajuda do comando selecionado.

install-agents

# Instalação nova
governancekit --root /projeto install-agents

# Atualização de uma instalação existente
governancekit --root /projeto install-agents --upgrade
ParâmetroDescrição
--ref REFTag, branch ou commit do AI-Agents. Padrão: v1.1.6, com checksum conhecido.
--repo OWNER/REPOOrigem alternativa. Padrão: EDortta/AI-Agents. Uma origem personalizada não possui checksum pré-conhecido.
--forceSobrescreve arquivos existentes. Use somente após revisar o impacto.
--upgradeAtualiza arquivos pertencentes ao kit e preserva estado e documentação do projeto.
--migrate-contentCom --upgrade, extrai contratos legados específicos do projeto de .docs-migration-bak/ para docs/project-rules/. Obrigatório antes de atualizar uma migração órfã.
--docs-onlyAtualiza somente documentação gerenciada; não toca AGENTS.md nem adaptadores das ferramentas.
--install-awtExecuta a instalação do helper agent-worktree.sh no PATH. É opt-in porque executa código baixado.
--trackMantém a documentação do kit rastreada no Git. A escolha fica em .governancekit.
--no-trackMantém a documentação do kit fora do Git. É mutuamente exclusivo com --track.

configure e identidade

O arquivo canônico é .governancekit-identity.json. Ele é local, gitignored e gravado com modo 0600. WORKSPACE.md não é exigido pelo runtime e não substitui essa identidade.

# Interativo
governancekit --root /projeto configure

# Não interativo
governancekit --root /projeto configure \
  --operator-name "Nome" \
  --host-id "host-01" \
  --instance-path "/projeto" \
  --sibling-path "/outro-checkout" \
  --assigned-ports "3000,8000" \
  --branch-ownership "feature/minha-branch"
ParâmetroObrigatórioDescrição
--set KEY=VALUENãoPreenche placeholder legado. Pode ser repetido.
--operator-name NAMESimNome do operador humano.
--host-id IDSimIdentificador estável desta máquina ou instância.
--instance-path PATHSimCaminho absoluto deste checkout.
--sibling-path PATHNãoCheckout irmão que pode disputar branch ou recursos.
--assigned-ports PORTSNãoPortas reservadas, separadas por vírgula.
--branch-ownership BRANCHNãoBranch ou branches pertencentes a esta instância.

Ao usar flags, forneça todos os campos obrigatórios. Sem flags, um terminal interativo pergunta os valores ausentes.

doctor

governancekit --root /projeto doctor
governancekit --root /projeto doctor --json
--jsonProduz resultado estruturado para CI. Falhas obrigatórias deixam ok: false; avisos consultivos permanecem identificados.

Valida arquivos obrigatórios, flags de prontidão, identidade local, segurança básica, estado do kit e possíveis colisões de branch.

map

governancekit --root /projeto map [--output PATH] [--all]
--output PATHDestino do mapa. Padrão: docs/codemap.md.
--allInclui símbolos privados cujo nome começa com sublinhado.

resume

governancekit --root /projeto resume

Mostra trabalho ativo, branch, próximo passo, identidade operador@host e alertas de colisão com checkout irmão. Não possui parâmetros próprios.

context inspect e context build

governancekit --root /projeto context inspect \
  --task implementation --risk runtime --issue docs/issues/ativa.md --json

governancekit --root /projeto context build \
  --task review --risk security --telemetry
--task TIPOSeleciona o conjunto de contratos da tarefa. Padrão: implementation.
--risk RISCOAdiciona uma categoria de risco. Pode ser repetido.
--issue PATHInclui a issue ativa na seleção.
--manifest PATHUsa um manifesto de contexto alternativo.
--jsonEmite seleção, contagens e decisões em JSON.
--telemetrySomente em build; registra metadados de uso sem capturar conteúdo.

inspect explica o que seria carregado; build materializa o contexto selecionado.

context telemetry prune

governancekit --root /projeto context telemetry prune [--manifest PATH]

Remove registros de telemetria mais antigos que a retenção declarada no manifesto. --manifest seleciona um manifesto alternativo.

Configuração de projeto, classificação e retomada

governancekit --root /projeto configure-project plan --project-name "Demo" --domain backend --capability api --agent openai-agents --provider openai:env:OPENAI_API_KEY:primary --json
governancekit --root /projeto classify-change plan --summary "Mover fronteira de autenticação" --label migration --label contract-change --rationale "Chamadores existentes precisam se adaptar" --domain backend --capability api --compatibility "unsafe in any order" --residual-risk "rollout manual" --json
governancekit --root /projeto config-session start --interactive
governancekit --root /projeto config-session approve --approval project-config-review
governancekit --root /projeto config-session apply

config-session start --interactive lê as fontes listadas em docs/required-reading.md, usa o idioma operacional e conduz a definição de escopo com explicação, exemplo e espaço visual antes de cada resposta estruturada. Registra agente escolhido, domínio primário de cada capacidade e, para cada provider, finalidade, papel de roteamento, modo e apenas a referência da credencial; a chave nunca vai para a configuração do projeto. Arquivos locais de credencial são protegidos e ignorados pelo git. O diálogo interativo iniciado pelo operador em install-agents e install-agents --upgrade aceita links simbólicos sob .credentials/, sem ampliar o acesso às fontes. No config-session direto, quando um link resolve fora do projeto, use --credential-root PATH antes do comando. Um perfil JSON pode conter api_key (ou apiKey/key) e opcionalmente model e base_url; os valores são usados somente em memória. primary é o padrão, fallback é usado quando ele falha e optional não participa do roteamento padrão. Valores salvos ou pendentes reaparecem como defaults no próximo upgrade. Uma sessão pending_approval significa que o plano está salvo em .gk/config-session.json, mas ainda não foi aplicado: execute config-session approve --approval <token> para cada aprovação listada, confira com config-session show e então execute config-session apply. O terminal imprime os comandos exatos e explica o que cada aprovação revisa. O estado compartilhável vai para .gk/project-config.json.

Issues locais, hooks e voz opcional

governancekit --root /projeto bootstrap-issue --epic-number 010 --epic-title "Adotar nova fronteira de autenticação" --task-title "Criar task de migração" --owner "Ann" --related-commit planned
governancekit --root /projeto install-hooks --hook-type pre-commit --force --json
governancekit --root /projeto voice-integration detect --json

bootstrap-issue usa as flags --epic-number, --epic-title, --task-title, --owner e --related-commit. install-hooks usa --hook-type e --force. A detecção de voz continua opcional e não torna o AI-ListenToMeOnCLI dependência obrigatória.

Sequências usuais

Primeira configuração

governancekit --root /projeto install-agents
governancekit --root /projeto configure
# preencher .docs/software-overview.md e .docs/limits.md
governancekit --root /projeto doctor

Atualização segura

governancekit --root /projeto --version
governancekit --root /projeto install-agents --upgrade
governancekit --root /projeto doctor

CI

governancekit --root "$GITHUB_WORKSPACE" doctor --json
governancekit --root "$GITHUB_WORKSPACE" context inspect --task review --risk security --json
scripts/validate-governance.sh "$GITHUB_WORKSPACE"
